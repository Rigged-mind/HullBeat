# Seed-каталог

Джерело істини для розділів і вузлів обслуговування. Похідне від
[../docs/taxonomy.md](../docs/taxonomy.md).

## Файли

| Файл | Призначення |
|---|---|
| `catalog.json` | Сам каталог: 21 категорія, ~230 вузлів |
| `schema.json` | JSON Schema (draft-07) для валідації |
| `../tools/validate_catalog.py` | Валідатор: унікальність кодів, посилання, словники |

## Куди потрапляє в збірці

`catalog/catalog.json` → `app/src/main/assets/catalog/catalog.json`
Копіюється Gradle-таском на етапі `preBuild`. Джерело редагуємо тут, в assets не чіпаємо.

## Мови

**У JSON немає перекладів.** Кожен вузол має `code` і англійський `en` як фолбек.
Локалізовані назви живуть у `strings.xml` за ключем `cat_<code>` / `cmp_<code>`:

```xml
<string name="cmp_raw_water_impeller">Імпелер забортної помпи</string>
```

Причина: 7 мов × 230 вузлів усередині JSON зробили б файл некерованим, а Android
і так має нормальний механізм локалізації з плюралізацією та fallback-ланцюжком.
Відсутній переклад → показуємо `en`.

## Поля вузла

| Поле | Обовʼязкове | Опис |
|---|---|---|
| `code` | так | Унікальний по всьому каталогу, snake_case |
| `en` | так | Англійська назва (фолбек) |
| `crit` | так | `high` \| `med` \| `low` — сортування при однаковій простроченості |
| `sched` | ні | `{days?, hours?, miles?}` — дефолтний регламент |
| `verify` | ні | `true` = інтервал ОБОВʼЯЗКОВО звірити з мануалом виробника |
| `appliesTo` | ні | Звужує застосовність усередині категорії |
| `parent` | ні | `code` батьківського вузла (підвузол) |
| `specHints` | ні | Підказки полів для паспорта вузла (`spec_json`) |
| `expires` | ні | Вузол має **явну дату закінчення**, яку вводить користувач |
| `reference` | ні | Ніколи не настає; зберігається лише для довідки |

### `sched` проти `expires` — вони не суперечать одне одному

Це два різні джерела дати, і в багатьох вузлах безпеки потрібні обидва:

- **`sched`** рахує наступний термін **від дати останнього обслуговування**.
  Це оцінка, якою заповнюємо порожнечу, поки користувач нічого не ввів.
- **`expires`** означає, що на предметі є **надрукована дата**, яку користувач
  вводить сам — і вона **перекриває розрахунок**.

Приклад: рятувальний пліт має `sched.days = 1095` (сервіс раз на 3 роки) **і**
`expires: true`. Поки сертифіката немає — показуємо оцінку «через 3 роки від останнього
сервісу». Щойно власник ввів дату з сертифіката — вона стає істиною.
Те саме з фальшфейєрами, картриджами жилетів, батареєю EPIRB, вогнегасниками.

`reference` виключає обидва: `ce_certificate` не «настає» ніколи.

## Правила застосовності (`appliesTo`)

Всі ключі — АБО всередині себе, І між собою. Порожній обʼєкт = підходить усім.

```json
{"propulsionAny": ["inboard_diesel", "saildrive"], "extrasAny": ["genset"]}
```

Словники значень — у `catalog.json` → `profileVocabulary`.

## ⚠️ Дефолтні інтервали

Це **орієнтири, не істина**. Усі редаговані користувачем.
Вузли з `"verify": true` при першому показі супроводжуються плашкою
«перевірте за мануалом двигуна» — ставити свої числа як авторитетні не можна.

Джерела орієнтирів: загальноприйнята практика з форумів і чеклістів
у `../pages/`, чеклісти Bavyn, публічні сервісні інтервали.
**Перед релізом звірити з мануалами Volvo Penta / Yanmar / Mercury**
([../docs/taxonomy.md](../docs/taxonomy.md), п.10).

## Журнал змін

### v6–v7 — 2026-09-05

**Новий вимір профілю: `cooling`** — `raw_water` або `keel_cooled`.

Кільове охолодження замкненого контуру (Fernstrum Gridcooler і подібні) майже
завжди йде в парі зі сталевим сухим глушником і термоізольованою вихлопною трубою
замість ватерлока й мокрої магістралі. Це **не варіант виконання, а інший склад
каталогу**.

Без цього виміру власник із сухим вихлопом бачив би сім вузлів, яких у нього
фізично немає:

| Показувати лише при `raw_water` | Показувати лише при `keel_cooled` |
|---|---|
| `raw_water_impeller` | `keel_cooling` |
| `raw_water_strainer` | `dry_exhaust_silencer` *(новий)* |
| `heat_exchanger` + `heat_exchanger_anode` | `exhaust_bellows` *(новий)* |
| `mixing_elbow` | `egt_monitoring` *(новий)* |
| `exhaust_hose` (ватерлок) | |
| `anti_siphon` | |
| `sea_chest` | |

Зникає ризик гідроудару — зʼявляється регламент контролю температури вихлопних
газів, компенсаторів розширення й термоізоляції. Три нові вузли саме про це.

`coolant` і `thermostat` не прив'язані до жодного варіанта: замкнений контур
є в обох.

**Питання в онбордингу ставиться лише власникам інбордного дизеля** — решті
воно не має сенсу, а онбординг тримаємо коротким.

**Три вузли перенесено до корпусу.** Власник шукає за функцією в судновій системі,
а не за типом фурнітури:

| Ключ | Було | Стало |
|---|---|---|
| `steering_cables_sheaves` | Рангоут і біжучий такелаж | **Корпус**, дочірній до `steering_system` — «Steering cables, chains & idler sheaves» |
| `sprayhood_bimini` | Камбуз та інтер'єр | **Корпус**, біля палуби — «Canvas (sprayhood, bimini, covers)» |
| `washboards` | Камбуз та інтер'єр | **Корпус**, біля люків — «Companionway hatch, washboards & lock» |

Штуртроси стоять поруч із пером, квадрантом і аварійним румпелем; брандерщит —
поруч із люками, бо це елемент водонепроникності сходного трапа.

### v5 — 2026-09-05

**+24 вузли** за списком власника (294 → 318). Корпус, двигун, паливо, електрика,
стоячий і біжучий такелаж, якірне, безпека, інтер'єр.

**Три наявні записи довелося розвести**, бо нові з ними перетиналися:

| Ключ | Було | Стало | Чому |
|---|---|---|---|
| `wind_gen` | Wind / hydro generator | **Wind generator** | зʼявився окремий `hydrogenerator` |
| `backstay` | Backstay / runners | **Backstay** | «runners» тепер окремий `running_backstays` |
| `tracks_cars` | Tracks & cars | **Genoa tracks & cars** | щоб не плутати з `mainsheet_traveler` |

Це той самий принцип, що й у v2–v3: один запис — один предмет.

**Нове поле схеми: `perEngine` на рівні вузла.**

`sea_chest` потрапив у категорію `engine_main`, у якої стоїть `perEngine: true` —
тобто на човні з двома двигунами вузол дублюється. Але січест **один на обидва
двигуни**, і дублювання створило б на човні другий, якого не існує.

Замість того щоб переносити вузол в іншу категорію, додано перекриття:

```json
{"code": "sea_chest", "en": "Engine sea chest", "crit": "high",
 "sched": {"days": 365}, "perEngine": false}
```

Валідатор стежить, щоб `perEngine: false` не ставили поза `perEngine`-категорією,
а `perEngine: true` не дублювало те, що вже вирішила категорія.

**Словник профілю:** до `extras` додано `hydrogenerator`.

## Версіонування й міграції

`version` збільшується на кожну зміну складу каталогу.

Правило міграції — **каталог ніколи не перезаписує дані користувача**:

1. Нові вузли зʼявляються як «доступні до додавання», не вставляються силою.
2. Перейменування в каталозі **не міняє** назву, яку користувач уже змінив
   (звʼязок тримається через `catalog_code`).
3. Зміна `sched` не чіпає регламенти, які користувач уже редагував.
4. Видалений з каталогу вузол у користувача **архівується**, а не зникає.
